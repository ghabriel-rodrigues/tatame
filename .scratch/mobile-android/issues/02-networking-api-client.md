# Networking & API client

Type: research
Blocked by: 01
Status: resolved

## Question

Which HTTP stack talks to the NestJS backend: Retrofit (+ OkHttp) vs Ktor Client, with `kotlinx.serialization` for JSON? Compare coroutine ergonomics, interceptor/plugin model (auth header injection, refresh, logging), error modeling, and testability. Also evaluate OpenAPI codegen from the backend's spec (openapi-generator kotlin generators, Fabrikt, or hand-written DTOs) — codegen fidelity with `kotlinx.serialization`, nullability correctness, and how generated code is versioned/regenerated inside the standalone Gradle project. Recommend the stack and the codegen workflow.

## Answer

Decision by BOSS (AFK), aligned with backend ticket 04 (`.scratch/backend/issues/04-*`: REST + OpenAPI 3.0.x spec committed at `packages/api-contract/openapi.json`, `jvm-retrofit2` template already validated there) and with the toolchain locked in ticket 01 (AGP 9.0.1, Kotlin 2.3.20, KSP-only, minSdk 26, single `:app`).

### Decision: Retrofit 3 + OkHttp + kotlinx.serialization, client generated by openapi-generator (`kotlin` / `jvm-retrofit2`)

**Stack (version-catalog entries):**

| Piece | Choice | Notes |
|---|---|---|
| HTTP engine | OkHttp 5.x | Stable since mid-2025; interceptors + `Authenticator` are the auth backbone |
| API layer | Retrofit 3.x | No annotation processor at all (runtime proxies) — zero KSP/kapt surface; native `suspend` support |
| JSON | kotlinx.serialization (runtime 1.8+) + **first-party** `com.squareup.retrofit2:converter-kotlinx-serialization` (same version as Retrofit) | Wharton's standalone converter was upstreamed into Retrofit and archived — use the Square artifact, not `com.jakewharton.retrofit` |
| Codegen | openapi-generator, generator `kotlin`, `library=jvm-retrofit2`, `serializationLibrary=kotlinx_serialization`, `useCoroutines=true` | The exact combination backend-04 validated; recent generator releases fixed `@Serializable`-on-enum gaps (PR #21907) — pin a current generator version in the catalog |

**Why not Ktor client:** the client library itself is fine, but (a) backend-04 explicitly rejected the ktor/multiplatform generator templates (pinned to dated Ktor, datetime issues) and this app is native JVM Android, not KMP; (b) OkHttp's `Authenticator` gives the cleanest single-flight 401 refresh; (c) MockWebServer (ticket 07) is the best-in-class test double and is OkHttp-native; (d) Ktor's Auth plugin refresh-token behavior has historically been quirkier than the OkHttp pattern. Retrofit also keeps us inside the Android mainstream the JetBrains java-to-kotlin skill guides already cover.

**JSON config (single shared `Json` instance in `core/network`):** `ignoreUnknownKeys = true` (server may add fields), `coerceInputValues = true` (unknown enum → default where declared), `explicitNulls = false`. Money is integer cents + currency and IDs are opaque strings per backend conventions — no BigDecimal in the contract, which sidesteps the known `@Contextual`/BigDecimal generator gap (#20944). Timestamps arrive ISO-8601 UTC strings; convert at the edge (kotlinx-datetime in mappers, not in generated DTOs).

### Codegen workflow (committed-generated, mirroring `LumiraTokens.kt`)

- Input: the committed spec `packages/api-contract/openapi.json` — the only artifact crossing from the nx world (same "sanctioned crossing" rule as the token file, ticket 01).
- The Android Gradle project registers the `org.openapi.generator` Gradle plugin with an **explicit, manually-invoked** task `generateApiClient` (not wired into `preBuild`) that reads the spec via relative path and emits into `app/src/main/kotlin/br/com/tatame/core/network/generated/` (`packageName=br.com.tatame.core.network.generated`, models + `apis` only; skip generator-supplied "infrastructure" auth/date helpers where config allows — we own the client wiring).
- Output is **committed**, marked generated-do-not-edit. Regeneration trigger: any change to `openapi.json`. CI freshness check: the Android CI job runs `./gradlew generateApiClient` + `git diff --exit-code` on the generated dir (parallel to the backend-side spec freshness check in backend ticket 08).
- Hand-written code never edits generated files; adaptation happens in wrappers (below). If generator output quality ever degrades on an upgrade, the committed copy means builds never break — we just don't take the upgrade.

### Auth wiring (interfaces here, storage decision in ticket 04)

- **Attach**: an OkHttp application interceptor reads the access token from an in-memory `SessionTokenProvider` (process-lifetime holder, never persisted) and sets `Authorization: Bearer`.
- **Refresh**: an OkHttp `Authenticator` handles 401s with **single-flight** semantics — a `Mutex`; on entry, if the in-memory access token already differs from the one that got the 401, another caller refreshed first → retry with it; otherwise call the refresh endpoint (on a bare Retrofit/OkHttp instance without the Authenticator, to avoid recursion), swap tokens, retry. Give up (→ session-expired signal to the auth state flow) after one refresh failure or when the refresh token is absent/rejected.
- **Storage primitive**: `core/network` depends only on a `TokenStore` interface (read/write/clear refresh token). Ticket 04 owns the implementation choice; BOSS steer for 04: `EncryptedSharedPreferences` is deprecated — prefer **Jetpack DataStore (Preferences) with values AES-GCM-encrypted under an Android Keystore key** (no Tink dependency needed for one secret); access token stays memory-only. Networking is agnostic either way — coordination note recorded, nothing here blocks on 04.
- Logging: `okhttp-logging-interceptor` in debug builds only, `redactHeader("Authorization")`.

### Error mapping: problem+json → sealed `ApiError`

Backend emits RFC 9457 `application/problem+json` `{ type, title, status, detail, instance, code, errors? }`; clients branch on `status` + stable `code`, never `title`. Generated APIs return `Response<T>`/throw; a hand-written wrapper in `core/network` normalizes:

- `suspend fun <T> apiCall(block): ApiResult<T>` where `ApiResult<T> = Success(T) | Failure(ApiError)`.
- `sealed interface ApiError`: `Network` (IOException, offline), `Timeout`, `Auth.SessionExpired`, `Auth.Forbidden` (RBAC), `Tenant.AcademySuspended`, `Tenant.ReadOnly` (delinquency), `Validation(fieldErrors)` (422 `errors[]`), `NotFound`, `Conflict`, `Server(status)`, `Unknown(status, code?)`.
- Mapping table keyed on `code` (mirrors the shared registry in `packages/shared`); unknown codes fall through to status-based buckets, never crash. `ProblemDetails` is a hand-written `@Serializable` DTO (stable shape, not worth generating).
- Suspension/read-only errors are surfaced to the session layer (ticket 04) as state, not just per-call failures.

### Implications

- **Ticket 04**: consumes `TokenStore` + `SessionTokenProvider` + the Authenticator's session-expired signal; owns storage primitive (DataStore + Keystore steer above), cold-start restoration, and auth-state flow.
- **Ticket 06 (DI)**: `Json`, `OkHttpClient` (authed + bare), `Retrofit`, generated API interfaces, and the wrapper are DI-provided singletons — trivial in either Hilt or Koin; no processor requirement added by this stack.
- **Ticket 07**: MockWebServer is the networking test tool; `apiCall`/error mapping and the single-flight Authenticator are pure-JVM testable.
- **Ticket 05**: QR check-in posts through this same client; nothing special.
